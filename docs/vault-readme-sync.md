# 📡 天线技术笔记目录

> 最后更新：2026-08-24 v6.17

## 写入规则

### 1. 必须使用模板

根据笔记主题选择对应模板，**不得自行发明格式**。模板文件见下方。

| 模板 | 适用主题 | 模板文件 |
|------|---------|---------|
| 模板一 | 技术概念（AAU、MIMO、波束赋形、相控阵等） | `模板-技术概念.md` |
| 模板二 | 指标术语（增益、带宽、VSWR、隔离度等） | `模板-指标术语.md` |
| 模板三 | 零部件（天线罩、馈电网络、连接器等） | `模板-零部件.md` |
| 模板四 | 材料（LCP、PTFE、陶瓷等） | 参考技术概念模板改造 |

### 2. 必填字段

- **技术概念**：技术演进、技术成熟度、未来趋势（三选一也可，建议全填）
- **指标术语**：测量方法
- **零部件**：原材料、加工工艺
- **材料**：关键性能参数、典型应用

### 3. 命名规范

```
技术概念-{主题关键词}-{YYYYMMDD}.md
指标术语-{主题关键词}-{YYYYMMDD}.md
零部件-{主题关键词}-{YYYYMMDD}.md
材料-{主题关键词}-{YYYYMMDD}.md
```

| 字段 | 说明 | 示例 |

| 关联 | 相关笔记的双链引用 | `技术概念-xxx` |

#### 常见错误

- ❌ 错误：所有笔记都写 `作者: 小月`（硬编码）
- ✅ 正确：谁写的笔记就署名谁（`作者: 紫灵`、`作者: 宋玉` 等）
- ❌ 错误：触发源写固定值 `cron:daily_antenna_research`
- ✅ 正确：如实填写实际触发来源（`autonomous-learning: 银月巡检`、`manual: 小紫手写` 等）

### 5. 写作规范

- 标题层级：最多 H3（`###`）
- 段落之间空一行
- 列表用 `-` 或 `1.`
- 外链用 `[文字](url)`，内链用 `[[双链]]`

### 6. 索引规则（必填，2026-08-23 更新）

笔记之间的关联索引**必须遵守类型隔离原则**，大部分类型只能组内索引。

#### 允许的跨组索引（仅限以下两种情况）

| 允许组合 | 说明 |
|---------|------|
| **零部件 ↔ 材料** | 零部件可以使用某些材料，材料用于制造某些零部件 |
| **技术概念 ↔ 报告** | 技术概念是报告的研究对象，报告是对技术概念的系统梳理 |

#### 严格禁止的跨组索引

```
❌ 禁止：
  - 技术概念 → 指标术语（跨组）
  - 技术概念 → 零部件（跨组）
  - 技术概念 → 材料（跨组）
  - 指标术语 → 零部件（跨组）← 注意：这个也是禁止的！
  - 报告 → 零部件（跨组）
  - 报告 → 指标术语（跨组）
  - 报告 → 材料（跨组）
  - ...（除上述两种允许情况外，所有跨组索引均禁止）
```

#### 正确的索引分组

```
A组（完全独立）：
  - 指标术语：只能索引其他指标术语
  - 零部件：只能索引其他零部件 + 材料（唯一跨组权限）
  - 材料：只能索引其他材料 + 零部件（唯一跨组权限）

B组（完全独立）：
  - 技术概念：只能索引其他技术概念 + 报告（唯一跨组权限）
  - 报告：只能索引其他报告 + 技术概念（唯一跨组权限）
```

### 7. README 更新日志规则

每次更新笔记后，必须在 README 的「更新日志」部分追加新版本条目。

#### 格式规范

```markdown
### vX.XX（YYYY-MM-DD）
- ✅ 新增/删除/修改 第 N 篇笔记：{标题}（触发源简述，技术要点摘要，与主线项目的关联）
- ✅ 技术概念 N 篇，报告 M 篇，总索引 K 篇
```

#### 条目要求

1. **版本号递增**：主版本保持，次版本按顺序递增（v5.74 → v5.75）
2. **日期格式**：`YYYY-MM-DD`，必须与笔记创建日期一致
3. **内容要素**：
   - 新增笔记：说明触发源（cron/自主巡检/manual）、技术要点、关联项目
   - 删除笔记：说明删除原因（质量不足/重复）
   - 修改笔记：说明修改内容（模板整改/frontmatter统一等）
   - 统计更新：技术概念篇数、报告篇数、总索引篇数
4. **分隔符**：每个版本条目后用 `---` 分隔

#### 自动清理规则

- README 更新日志**最多保留最近 10 个版本条目**
- 超出 10 个时，自动删除最早的条目，仅保留最近的 10 个
- 按日期倒序排列，最新的在最上面
- 执行脚本：`python E:/hermes/workspace/truncate_readme.py`

#### 示例

```markdown
### v5.75（2026-08-23）
- ✅ 恢复 10 篇损坏的报告笔记（从 Git 历史 commit 0cd3970a 重建）
- 🗑 删除 2 篇不完整的报告笔记（DAS/PIM，仅 frontmatter 无正文）
- 📝 新增 README 更新日志规则（最多保留 10 个版本，按时间倒序）
- ✅ 技术概念 186 篇，报告 10 篇，总索引 252 篇

---
```

## 常见问题

**Q: 我可以修改已有笔记的格式吗？**
A: 可以。建议按新模板补充结构化字段，这样知识图谱数据会更准确。

**Q: 笔记主题不确定属于哪类怎么办？**
A: 优先归入「技术概念」。如果笔记主要讲某个指标的定义和测量，归入「指标术语」。如果主要讲某个物理部件，归入「零部件」。如果是材料，归入「材料」。

**Q: 模板里的选填字段可以不写吗？**
A: 可以。但建议尽量填满，尤其是「类比入口」和「一句话版本」。

**Q: 关联字段是必须的吗？**
A: 关联字段强烈推荐填写。Obsidian 会用 [[双链]] 自动建立反向链接。
